# AGENTS.md — Bit World (`lib/examples/bit_world/`)

Technical reference for building, updating, and verifying **Bit World**, the 3-act `pygraphics` + `synthio` pixel-art showcase in the `gallery` repository.

## 1. App Overview & Design Decisions

- **Entry & Package**: `lib/examples/bit_world/bit_world.py` (with `__init__.py` re-exporting it), discovered by `scripts/gallery_generator.py` as a manifest package (`?manifests=bit_world`) with card title **Bit World**.
- **Header Directives** (must stay within the first 10 lines of `bit_world.py`, after the 3 SPDX lines):
  ```python
  # gallery: featured, newwindow
  # deps: audiodsp, multimer, pygraphics
  ```
  - `featured, newwindow` pins the card to the top Featured section of `.site/gallery/index.html` and opens `micropython.html?manifests=bit_world` in a new browser tab (`target="_blank"`) so the `800x480` canvas gets full-page width.
  - `validate_example_deps` in `scripts/gallery_generator.py` AST-parses every `.py` file in the package and compares top-level imports against `INSTALLABLE_DEPS` (`{"palettes", "pygraphics", "pdwidgets", "audioinstruments", "audioeffects", "controlkit"}`). Any imported module from that set must be listed in `# deps:`, and any unused `# deps:` prints a warning. (`audiodsp` and `multimer` map to `_DEP_TIER` badges).
- **Resolution & Scaling**:
  - Target landscape resolutions: `480x320` up to `800x480`.
  - Before `import board_config`, set defaults only when unset so `tools/screenshot.py --resolution ...` and user env vars still work:
    ```python
    from boarddev import env_get, env_set

    if env_get("PYDEVICES_WIDTH") is None:
        env_set("PYDEVICES_WIDTH", 800)
        env_set("PYDEVICES_HEIGHT", 480)
    if env_get("PYDEVICES_SCALE") is None:
        env_set("PYDEVICES_SCALE", 1.0)
    ```
  - If a display opens in portrait (`display_drv.width < display_drv.height`, such as a `320x480` panel or `screenshot.py`'s `240x320` thumbnail run), rotate 90 degrees (`display_drv.rotation = (display_drv.rotation + 90) % 360`) before reading `WIDTH = display_drv.width` and `HEIGHT = display_drv.height`.
- **Pure `.py` App Assets (No Binaries in `lib/examples/bit_world/`)**:
  - `scripts/install_gen_manifests.py` only packages files with suffixes in `MIP_FILE_SUFFIXES = {".py", ".mpy", ".json", ".html"}`. Examples that rely on `.bmp`/`.png` files must be marked `# gallery: binaries`, which excludes them from the web gallery (`ex.in_gallery = False`).
  - Therefore, all sprites, tiles, palettes, animations, and synth patches in `lib/examples/bit_world/` must be pure `.py` modules.
  - The single gallery card thumbnail at `.site/pyscript/thumbnails/bit_world.png` is generated by `scripts/gallery_generator.py` (via `tools/screenshot.py`).
- **Three Acts + Seamless Attract Mode**:
  - **Act 1 (`act_pet.py`) — Bit's Workshop**: Cozy Sci-Fi / Solarpunk maker desk with **Bit** (hovering CRT-faced robot companion), expressive CRT faces, eye-tracking, floating pixel emotes, steaming coffee mug, glowing bonsai terrarium, starry night window, live holo-widgets, typewriter speech bubble + voice waveform, and interactive action buttons (`GREET`, `SING`, `SCAN`, `COFFEE`, `NAP`).
  - **Act 2 (`act_game.py`) — Bioluminescent Sky Ruins**: 4-layer parallax side-scrolling platformer/jetpack runner with spinning energy crystals, hovering patrol drones, plasma bolts, particle bursts, and combo popups.
  - **Act 3 (`act_deck.py`) — Solarpunk Reactor & Synth HMI**: Machine UI dashboard with dual radial gauges (`arc` + `polygon` needles), live dual-trace oscilloscope & 16-band spectrum synced to `synthio`, animated coolant fluid tank with bubbles, tactile toggle switches (`BOOST`, `SHIELD`, `PHASE`, `OVERDRIVE`), `THROTTLE` fader, 8-pad harmonic matrix, and mini-Bit holo-monitor.
  - **Attract Mode (`AUTO`) vs Manual**: Runs hands-free by default (auto-demonstrating interactions within each act and cycling acts every ~18s with a Bayer-dithered pixel wipe). Any pointer click, touch, or key press inside an act switches to manual control, or users can click the top stage bar tabs (`1: WORKSHOP`, `2: SKY RUINS`, `3: CYBER DECK`, `AUTO/MANUAL`, `SOUND`).

## 2. `pygraphics` Runtime & WASM Findings

Inspection of `pygraphics` (`native_cmod` and `pygraphics_python`) and the browser `micropython.wasm` runtime:

1. **Compiled C Module (`native_cmod`) vs Pure-Python (`pygraphics_python`)**:
   - `bin/micropython` and `micropython.wasm` use the native C module (`pygraphics.implementation() == "native_cmod"`).
   - CPython uses `pygraphics_python` unless built in-place.
2. **Available `FrameBuffer` Methods Across All Runtimes (including WASM)**:
   - Present everywhere: `FrameBuffer(buf, w, h, RGB565)`, `.width`, `.height`, `.fill(c)`, `.fill_rect(x, y, w, h, c)`, `.rect(x, y, w, h, c, f)`, `.round_rect(x, y, w, h, r, c, f)`, `.gradient_rect(x, y, w, h, c1, c2, vertical)`, `.pixel(x, y, c)`, `.hline(x, y, w, c)`, `.vline(x, y, h, c)`, `.line(x1, y1, x2, y2, c)`, `.circle(x, y, r, c, f)`, `.ellipse(x, y, rx, ry, c, f, m)`, `.arc(x, y, r, a0, a1, c)`, `.triangle(x0, y0, x1, y1, x2, y2, c, f)`, `.poly(x, y, coords, c, f)`, `.polygon(points, x, y, c, angle, center_x, center_y)`, `.blit(source_fb, x, y, key)`, `.blit_rect(buf, x, y, w, h)`, `.blit_transparent(buf, x, y, w, h, key)`, `.scroll(dx, dy)`, `.text8(s, x, y, c)`, `.text14(s, x, y, c)`, `.text16(s, x, y, c)`.
3. **Critical `pygraphics` Details & Traps to Avoid**:
   - **`FrameBuffer.blit_alpha` is available on desktop and in WASM**: Both desktop `pydevices-pygraphics` (`0.1.3.dev1`) and the updated `micropython.wasm` on `PyDevices.github.io` include `FrameBuffer.blit_alpha(mask, x, y, w, h, color)`. `bit_sprites.py` stores 8-bit radial alpha glow masks inside its single `DATA = memoryview(b"..." ...)` constant and blends them directly via `fb.blit_alpha` with zero heap allocation.
   - **Do NOT use `FrameBuffer.from_bitmap` or `FrameBuffer.from_module`**: Those static methods exist only on the Python subclass in `_framebuf_plus.py` and do **not** exist on `native_cmod`'s `FrameBuffer`. Construct `FrameBuffer(bytearray_or_mv, w, h, RGB565)` directly.
   - **Out-of-Bounds Blit Trap (`blit` vs `blit_transparent` / `blit_rect`)**:
     - `fb.blit(source_fb, x, y, KEY)` safely clips negative `x`/`y` and off-right/off-bottom coordinates on **both** `native_cmod` and `pygraphics_python`.
     - `fb.blit_transparent(buf, x, y, w, h, KEY)` and `fb.blit_rect(buf, x, y, w, h)` raise `ValueError: The provided x, y, w, h values are out of range` on `pygraphics_python` (and `PSDisplay`) whenever `x < 0`, `y < 0`, `x + w > width`, or `y + h > height`.
     - **Rule**: Wrap every unpacked sprite/tile in a `pygraphics.FrameBuffer` and draw it onto the scene `FrameBuffer` with `scene_fb.blit(sprite_fb, x, y, KEY)`. Only call `display_drv.blit_rect(scene_buf, 0, 0, WIDTH, HEIGHT)` with full-frame or clamped in-bounds rectangles.
   - **Slice Assignment on Large `bytearray`s**: On MicroPython, `buf[a:b] = rhs` on a `bytearray` can reallocate/move the tail if not done through a `memoryview`. Always wrap `bytearray` in `memoryview(buf)` before copying row slices (`mv[a:b] = bg_mv[a:b]`).
   - **`Draw.arc` and `FrameBuffer.poly` Signatures**:
     - `Draw.arc(x, y, r, a0, a1, c)` takes 6 positional arguments (no thickness parameter). Draw thick gauge rings with a concentric loop: `for dr in range(thick): d.arc(cx, cy, r - dr, a0, a1, c)`.
     - For filled triangles/needles, use `fb.poly(0, 0, array("h", [x0, y0, x1, y1, x2, y2]), c, True)` — `FrameBuffer.poly` accepts a flat `array("h")` identically on both `native_cmod` and `pygraphics_python`, whereas `Draw.polygon` on `pygraphics_python` indexes `points[i][0]` expecting 2-tuples.
   - **MicroPython String Slicing Restriction**:
     - MicroPython raises `NotImplementedError: only slices with step=1 (aka None) are supported` on `row[::-1]`. Never use `[::-1]` to mirror sprite rows; mirror horizontally via coordinate math `(src_w - rx - run) * scale`.
4. **Low-Allocation Frozen Asset Pattern (from `pydevices/packages/iconkit`)**:
   - Inspection of `pydevices/packages/iconkit` (`lib/iconkit/__init__.py`, `lib/iconkit/_a8_24.py`, `lib/iconkit/gfx.py`, `tools/make_icons.py`) shows how `.py` assets should be structured so they allocate almost nothing when frozen into firmware:
     - **Adjacent `bytes` literals wrapped in `memoryview`**: Put all binary/grid/mask data inside one `DATA = memoryview(b"..." b"..." ...)` constant. Python's compiler joins adjacent `b"..."` literals into a single constant at compile/freeze time, placing the entire blob in `.rodata` (flash). Indexing an individual asset via `DATA[offset : offset + length]` returns a `memoryview` slice without copying any bytes to heap RAM.
     - **Flat tuples instead of dicts for asset metadata**: Store asset names or `(offset, width, height)` descriptors in flat immutable tuples rather than building large dictionaries or nested lists of strings at import time.
     - **Direct `blit_alpha` from `memoryview` slices & buffer reuse**: With `fb.blit_alpha(mask_view, x, y, w, h, color)` (available in `pygraphics` and the updated WASM build), 8-bit alpha masks in `DATA` render directly from flash in any RGB565 color with zero intermediate buffer allocation. For multi-color scaled sprites, unpack from the contiguous `DATA` blob or reuse a single shared scratch buffer rather than allocating dozens of separate heap objects, and store lookup tables (`SIN256`, palette tables) as flat `bytes` or `array` constants rather than boxed integer tuples/dicts.

## 3. Audio (`synthio` + `audiodev`) Findings

We inspected `micropython.wasm` and `bin/micropython` for audio modules:

- **Compiled into `micropython.wasm` and `bin/micropython`**: `synthio`, `audiodev`, `audiomixer`, `audiodelays`, `audiofilters`, `audiofreeverb`, `audioinstruments`, `audioeffects`.
- **Why `synthio.Synthesizer` is ideal here**:
  - Renders directly in C inside the audio pump (`audio_out = board_peripherals.audio_out(latency="low")`, `audio_out.attach(app)`, `audio_out.play(synth)`) with zero Python per-block `fill()` timer overhead and instant scene transitions.
  - Supports custom 16-bit signed `array("h", ...)` waveforms (`_WAVE_SIZE = 256`), per-note `synthio.Envelope(attack_time, decay_time, release_time, attack_level, sustain_level)`, and `synthio.LFO(rate, scale, offset, once, waveform)` attached to `note.bend` or `note.amplitude` for expressive robot chirps, laser sweeps, and vibrato.
- **Browser Audio Unlock & `audio_out.attach(app)`**:
  - `audio_out = board_peripherals.audio_out(latency="low")` wraps the platform transport in `audiodev.sample_out.AudioOut`. You **must** call `audio_out.attach(app)` so `AudioOut.service()` is subscribed to `app.every(...)` and continuously pulls blocks from the C `audiopump` into the transport. Without `audio_out.attach(app)`, `audio_out.play(synth)` primes only the initial 512 frames and never advances `_played_frames`.
  - Browsers block `AudioContext` until the first user gesture (`pointerdown` or `keydown`), causing `audio_out.play(synth)` at startup to raise an exception.
  - In `.site/gallery/gallery-host.js`, `armAudioGesture()` listens for the first `pointerdown`/`keydown` and calls `state.enableAudio(false)`, which resolves asynchronously just after the gesture event.
  - Therefore, follow `piano.py` / `drum_machine.py`: attempt `audio_out.play(synth)` in `__init__` inside `try/except Exception`, retry on user input AND on each music step (`_trigger_music_step`) while `not self.ready and not self.muted`, and degrade gracefully when running under dummy/no-audio drivers.
- **Audio Verification**:
  - Attach `audiopump.Tap(frames=fmt.rate * 8, channel_count=fmt.channels)` via `audiopump.tap(tap)` while running `bit_world` on MicroPython and CPython to record the live pumped PCM stream (`tap.readinto(buf)`, reading at most `3/4` of capacity to avoid ring wrap tearing), then verify RMS, peak dBFS, fundamental `f0`, zero clipping, and zero dropouts.
  - In browser WASM (`/gallery/micropython.html?manifests=bit_world`), verify that clicking the canvas sets `window.Module.pydevicesBridge.permissions().audio === true` and advances `window.Module.pydevicesBridge.stats().queuedAudioBytes > 0`.

## 4. App Loop, Input & Display Contract

- **Timer & Poll Re-entrancy (`app.every` Callback Signature)**:
  - `app.every(ms, callback)` always invokes `callback(timer)` passing the `multimer` instance as the first positional argument. Always define tick callbacks as `def step(self, _timer=None):` so timer dispatch does not raise `TypeError: step() takes 1 positional argument but 2 were given`. When a timer callback fails, `multimer` prints the traceback once on the first tick, so check the top of the output if a frame comes out black.
  - Never call `app.poll()` inside an `app.every(...)` timer callback; sync backends (`librt`/`sdl2`) re-enter the timer path and hang. Check `if app.quit_requested: return` at the top of the tick callback.
- **Presenting Frames**:
  - Render each frame into an off-screen `FrameBuffer(screen_buf, WIDTH, HEIGHT, RGB565)` and push to the display with `display_drv.blit_rect(screen_buf, 0, 0, WIDTH, HEIGHT)`.
  - `appdev.App` automatically refreshes the display on its tick when `blit_rect` marks the display dirty (`needs_refresh`). Calling `display_drv.show()` on the first frame ensures `tools/screenshot.py` (which hooks `SDLDisplay.show` / `PGDisplay.show`) can capture frames deterministically.
- **Multi-Touch vs Mouse Deduplication**:
  - Primary touch contacts also synthesize `MOUSEBUTTONDOWN`/`MOUSEMOTION`/`MOUSEBUTTONUP` with `getattr(e, "touch", False) == True`. Ignore mouse events where `getattr(e, "touch", False)` is truthy if also handling `FINGERDOWN`/`FINGERMOTION`/`FINGERUP`, or handle `MOUSEBUTTONDOWN`/`MOUSEMOTION`/`MOUSEBUTTONUP` unified (since primary touch synthesizes mouse events on all backends).
- **Timekeeping Portability**:
  - Always import `ticks_ms`, `ticks_diff`, `ticks_add` from `multimer` (not `time`), because CPython and Pyodide `time` do not have `ticks_ms`.
- **Randomness Portability**:
  - MicroPython on Windows ships only `getrandbits` and `seed` in `random` (no `randint` or `choice`). Always provide a small helper using `getrandbits`.

## 5. Gallery Generator, Manifests, Thumbnails & Style Checks

After adding or updating files in `lib/examples/bit_world/`, run these commands from the repository root:

1. **Refresh MIP manifests and `gallery.toml`**:
   ```bash
   ./scripts/install_refresh_manifests.sh
   ./scripts/install_refresh_manifests.sh --audit
   ```
   - Runs `scripts/install_gen_manifests.py` (creates `packages/bit_world.json` and updates `packages/examples.json`) and refreshes `gallery.toml`.

2. **Generate Thumbnail & Refresh Gallery HTML/JSON**:
   ```bash
   python tools/screenshot.py bit_world 1.5 --resolution 800x480 --scale 0.5 -o .site/pyscript/thumbnails/bit_world.png
   python scripts/gallery_generator.py
   python scripts/gallery_generator.py --check
   ```
   - `tools/screenshot.py` resolves `bit_world` to `lib/examples/bit_world/bit_world.py` and places `lib/examples/bit_world/` on `sys.path`.
   - Set `BIT_WORLD_ACT=0`, `1`, or `2` in the environment to boot directly into Act 1 (Workshop), Act 2 (Sky Ruins), or Act 3 (Cyber-Deck) for screenshots.
   - `scripts/gallery_generator.py` updates `.site/gallery/index.html`, `.site/pyscript/index.html`, and `.site/gallery/python-files.json`.

3. **House Style Rules**:
   - Every `.py` file must start with:
     ```python
     # SPDX-FileCopyrightText: 2026 Brad Barnett
     #
     # SPDX-License-Identifier: MIT
     ```
   - No Sphinx roles (`:class:`, `:ref:`) or fields (`:param:`, `:returns:`) in docstrings.
   - No type annotations in code under `lib/examples/` (runs on MicroPython/CircuitPython).
   - Module docstring must have: one-line imperative summary (< 72 chars), short overview paragraph, `Needs:`, `Run it:`, and `Tested on:` in that order.

4. **Test Across Interpreters & Browser WASM**:
   - Desktop MicroPython: `MICROPYPATH=".:.frozen:lib:lib/examples/bit_world" micropython -X heapsize=8M lib/examples/bit_world/bit_world.py`
   - Desktop CircuitPython: `MICROPYPATH=".:lib:lib/examples/bit_world" circuitpython lib/examples/bit_world/bit_world.py`
   - Desktop CPython: `PYTHONPATH="lib:lib/examples/bit_world" python tools/screenshot.py bit_world 1.5 --resolution 800x480 --scale 1`
   - Browser WASM (Playwright): Serve `.site/` and load `/gallery/micropython.html?manifests=bit_world`, verifying `window.__pydevicesHost.phase === "ready"` and `window.__pydevicesHost.errors.length === 0`.
